# JMlab 模块开发

把用户的内容服务接入 JMlab 的统一模块接口，交付能导入、能配置、能热切换且经过本地验证的独立模块。具体内容服务的规则由模块实现，宿主继续负责媒体目录、用户权限、存储与兼容客户端入口。

## 先确认接入目标

从已有代码、用户要求和目标服务说明中确定：

- 目标 JMlab 版本或提交、模块 ID、开发语言、输出目录，以及服务器系统/架构；默认交付可安装 ZIP，独立部署时交付 JSON 连接清单。
- 需要 `metadata`、`stream` 还是 `composite`，以及支持的 `movie/series/season/episode/video`。
- 上游接口、认证方式、媒体标识、分页方式；视频是否有短期地址、请求头、字幕或私网访问。
- 需要用户设置的字段、管理操作、虚拟库模板、榜单、宿主存储、跨模块调用或事件。

只询问会影响实现且现有资料无法推断的信息。使用通俗中文，给出推荐选项；缺少真实账号时先用独立测试服务开发，不编造上游接口或将模拟结果报告为真实验收。

## 找到当前可执行契约

本 Skill 随宿主源码维护，包含本地 ZIP 安装与网址导入约定。先核对目标版本的 `internal/module/packages.go`、`runtime.go` 及指南；[旧 HTTP 基线 2d564c9](https://github.com/graysui/JMlab/tree/2d564c9eca1047614ad70c0c84a3503749a41d8c) 不含 ZIP 运行能力，不能将本轮新功能承诺给旧版镜像。

优先读取用户目标版本的 `docs/module-developer-guide.md`、`internal/module/contract.go`、`manifest.go`、`transport_http.go`，以及本次所需能力的实现。没有宿主源码时，读取该版本的官方仓库文件。遇到差异以目标实现为准，并在交付中说明兼容范围；不能直接用最新 main 覆盖用户固定版本的契约。

当前基线的重要边界：

- 外部模块使用独立的 **HTTP / JSON 服务**。`grpc` 和 Protobuf 是草案，不能承诺可运行；`in_process` 需要宿主代码注册。
- 所有类型都实现 `GET /api/v1/caps`，视频模块声明 `supportsStreams: true`。清单与非空 `supportedTypes` 的交集决定实际支持的媒体类型。
- 本地 ZIP 由宿主按 `runtime` 启停程序及更新版本，支持本地文件和公网网址导入；外部 JSON 只连接独立服务。两种模式均不自动安装依赖或执行旧 `entrypoint`。ZIP 程序遵守监听地址、Bearer 和持久化目录的环境变量约定，详见清单参考。
- 模块通过开放接口实现功能。只有确认公开协议缺少通用能力时，才提出宿主接口变更；不能增加特定模块 ID 的分支或专属前端页面。
- 在 JMlab 主项目中开发的具体模块放入 `local-modules/<module-id>/`；其他工作区遵循用户给定目录。不要把具体模块、凭据或运行数据加入主程序公开提交或镜像。

## 形成可用实现

先明确模块职责、媒体标识、交付模式和服务器平台，再完成与范围相符的实现，不要求用户先批准普通实现细节。ZIP 必须包含可运行程序及依赖，不能只压缩源码；目标不具备解释器时自带解释器或使用外部服务。

1. **对齐清单与实际能力。** 使用稳定 ID，列出真实支持的媒体类型；将上游字段映射为通用 `providerIds/entities/images/extraAttributes`。详情 ID 不随标题、画质或登录状态改变。
2. **实现请求边界。** 验证模块连接 Bearer，按请求解码 `X-JMlab-Module-Config`；配置与上游客户端按请求或不可变配置实例隔离。不能将一个用户的最新请求配置写入全局变量，污染另一个宿主或正在执行的旧请求。
3. **完成最小业务闭环。** 信息模块做到搜索或按 ID 导入、详情及幂等入库；视频模块做到发现、解析、探测并经宿主播放；复合模块完成两条链路。只声明已经实现的可选能力。
4. **把操作放进模块页面。** 用户可改配置放 `configSchema`；连接检查、刷新列表、账号维护等操作放 `actions`。声明清晰的中文字段、选项、展示列和必要的破坏性操作确认。无需用户手改秘密文件才能日常使用。
5. **补齐所需扩展。** 模板筛选已入库内容，榜单由宿主任务导入；宿主私有存储、授权调用及通知按清单声明启用。不要直接读写宿主数据库或依赖未声明的其他模块。
6. **验证宿主热切换。** 连接、凭据和能力变化通过管理器更新；模块按请求接收新配置。旧票据、旧媒体签名失效后重新获取，旧请求不能覆盖新实例结果。

上游请求应可取消、有界且可复用连接。普通 RPC 客户端上限为 10 秒和 8 MiB，视频发现和解析还有约 2 秒的单次预算；避免在请求内遍历全部上游目录、下载整部视频或无限重试。管理操作最多 10 秒、结果最多 1 MiB。耗时工作若需异步处理，由模块管理自己的任务并通过已声明操作查询状态，不编造宿主任务接口。

## 播放链路必须保留的语义

模块只返回候选和真实媒体信息，**无需自行实现 Jellyfin 服务端**。Web 与 Jellyfin 接口共用宿主播放服务和权限。

- 使用 `candidateId` 标识模块候选，`encryptedPayload` 保存不透明引用；它的名字不代表模块已经加密，也不该成为客户端可见地址。
- 在解析时获取短期真实地址与必要请求头，返回可信的容器、时长、64 位文件大小、轨道及字幕；未知值省略，不按清晰度猜编码。
- 模块流经宿主中继；媒体来源授权与模块 RPC 地址分开。私网需精确 `allowedOrigins` 与 `allowPrivate`，不能关闭全局网络校验。
- 宿主没有服务端转码、重新封装或内嵌字幕提取。协议测试通过只能证明接口链路，真实格式、拖动和解码需在目标客户端实测。
- 视频模块的 `libraryScope` 是宿主管理设置，不是模块秘密配置。范围决定提供视频的媒体，不增加用户权限。

## 交付与范围

交付独立模块源码、无秘密的 `manifest.json`、依赖声明、必要测试和使用说明。本地模式还需交付目标平台的 ZIP 与 SHA256，验证上传/网址读取、安装、启停、更新回退与重启恢复；外部模式写清独立启动方式及宿主可访问的地址。均说明凭据设置入口、能力范围、备份边界和更新方式。Compose 中的 `127.0.0.1` 指宿主容器自身；含凭据连接必须满足 HTTPS 或回环地址限制，不能为演示关闭验证。

按[验收清单](references/verification.md)完成与本次能力对应的本地检查，报告已实现、已验证、尚待真实服务或客户端验证的内容。默认不构建或发布 Docker、不部署远程服务器、不推送具体模块；只有用户明确要求时才执行相应外部发布工作。遵循所在仓库的提交要求，不把使用本 Skill 当成发布授权。
