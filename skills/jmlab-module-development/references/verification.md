# 本地验收与交付

按本次模块实际声明的能力选择检查。信息模块不必搭建无关视频服务；视频模块必须验证宿主播放链路，不能只用 curl 读取解析 JSON 就宣称客户端可用。

## 准备隔离环境

使用独立临时数据库、测试用户、随机连接令牌、测试密钥与端口，不读取真实 `.env`、部署连接说明或私人数据库。上游测试服务仅提供虚构内容及可控的短媒体、字幕和 HLS 资源，记录哪些结果仍需真实服务验证。

本地 ZIP 先准备自包含程序、核对服务器平台，再由宿主导入启动；外部 JSON 模式按自身依赖单独启动。宿主采用用户目标版本。容器内回环地址不是宿主机，含凭据连接仍需满足 HTTPS/回环校验，不能为了联调改宿主认证策略。当前默认只进行本地检查，Docker 构建和远程发布依用户明确要求执行。

## 清单及基础协议

| 检查 | 可观察结果 |
| --- | --- |
| 清单解析与导入 | 类型、ID、表单、模板、榜单、权限均通过目标宿主校验；未知或缺失能力得到明确反馈 |
| caps | 三种模块都能握手，类型交集符合预期；安装预检没有反向凭据也能完成 |
| 认证 | 错误/缺失 Bearer 被模块拒绝；伪造 Module-ID 不会绕过验证 |
| 请求配置 | 两组不同配置并发请求不会交叉使用上游账号；配置头的 null、错误 Base64、错误 JSON 和类型错误有明确处理 |
| 错误及超时 | 上游不存在、401/403、429、500、断线、慢请求、无效 JSON 分别有界返回，不泄漏响应正文或凭据 |
| 模块页面 | 字段、选项、操作、确认与展示列可用；秘密不在读接口、普通日志、消息或嵌套结果出现 |

只用 JSON 语法验证不足以检查契约。能访问宿主源码时，用 `module.Manifest.Validate()` 加实际安装预检验证；该方法本身也不是覆盖全部业务规则的 JSON Schema。

## 本地 ZIP 验收

- 读取本地 ZIP 及公网直链均只预览，不执行程序；平台错误、损坏文件、校验失败及越界/链接文件被拒绝。
- 实际安装后按随机回环端口运行，Bearer 被校验；业务配置按请求隔离，宿主密钥和管理员密码不出现在子进程环境或响应中。
- 停用停止程序，启用与主程序重启恢复；崩溃能重试，持续失败有退避。更新预检/保存失败保留原程序、配置与媒体状态。
- 更新保持秘密、适用库与 `.data` 文件；过期 revision/令牌、令牌重放和其他管理员使用令牌均被拒绝。
- 卸载停止进程树并移除程序，保留 `.data`、媒体、个人状态。配置备份不带程序；恢复后重新导入同 ID ZIP 可补齐程序并继续恢复。
- ZIP 包是可运行程序而非单纯源码。记录原生平台实测结果；交叉编译只代表生成文件，不代表目标容器或客户端已验收。

## 信息模块闭环

- 搜索分页、空结果、详情缺失均正确；同一 `sourceId` 重复导入得到同一媒体记录。
- 同数字 ID 的不同类型不混淆，同名不同人物 ID 不合并；不同角色能关联同一个实体。
- 剧集 → 季 → 单集按父子类型导入，包含正确 `parentId/indexNumber`；详情刷新遵守用户字段锁定。
- 模板在选择模块后出现；榜单范围与实际声明一致，已保存库筛选得到预期内容。
- 模板 revision 过期被拒绝并可重新读取；清单更新不覆盖已保存的库。
- 榜单任务按范围导入，故障与取消保留旧快照；自动更新默认关闭，停用模块时不执行。

## 视频模块闭环

至少完成 **已入库媒体 → 候选 → 解析 → 宿主授权 URL → 实际读取媒体**：

- 正片/预览不混淆，无候选不伪造默认地址；明确指定候选不会静默换成另一候选。
- 解析短期地址在过期后可刷新，缓存不跨配置复用；17 GiB 等大文件大小不会被截断。
- 通过宿主 URL 验证 Range 的 206、Content-Range 和小范围内容；不能用模块直接访问上游的结果替代。
- 如声明 HLS，验证主清单、子清单、密钥和分片都经签名重写与授权；如声明外挂字幕，验证字幕 URL、格式和用户权限。
- 不同候选的容器、音轨和字幕各自正确；未知属性不伪造。超时或旧实例返回不覆盖新版本结果。
- 用两个媒体库及不同权限用户验证 `libraryScope`；范围过滤和用户授权都生效。
- 经 Jellyfin 登录、目录与 PlaybackInfo 拿到正确来源，电影及单集可播放；音轨/字幕选择、关闭字幕和续播进度符合预期。
- 用目标客户端实测真实视频的解码、拖动、切换轨道与字幕；没有设备或上游凭据时明确标记未验收，保留可复现步骤。

## 热加载及宿主协作

1. 本地 ZIP 程序由宿主管理，外部服务保持独立运行；修改宿主配置或外部清单；新请求使用新配置，旧请求无法修改新实例状态。
2. 停用模块后不再参与发现和管理操作，原始媒体及个人进度仍保留；重新启用可重新握手。
3. 更新、重新启用或宿主重启后，旧 Host-Token/Call-Ticket/媒体签名失效，新业务请求收到有效凭据。
4. 已声明存储时，测试读写删、命名空间隔离与配额；未声明存储时回调被拒绝。
5. 已声明跨模块调用时，测试允许与拒绝的方法、停用目标、循环调用、票据过期与 429，不能通过模块服务自行改链。
6. 已声明事件时，测试重复 eventId、失败重试与停用取消；确认模块对丢事件有主动对账策略，不将通知当可靠队列。
7. 已声明返回 `configPatch` 的操作时，确认秘密只保存在宿主配置，旧注册凭据失效，失败时保留旧实例。

## 定位可复用的宿主回归

在 JMlab 源码仓库中，以下命令按改动范围选用，不要求每个模块都运行全部宿主测试：

```sh
go test -p 1 ./internal/module ./internal/modulehost ./internal/moduleadmin
go test -p 1 ./internal/integration ./internal/playback ./internal/jellyfin
```

第一组适合清单、配置、回调和热更新；第二组适合视频与兼容接口。模块自身使用所选语言的测试工具，覆盖实际上游适配、字段映射及失败行为。宿主测试通过不等于这个新模块已通过测试。

## 常见故障从哪里查

| 现象 | 优先核对 |
| --- | --- |
| 服务能访问，但宿主无法安装 | caps 路径与 JSON、连接 Bearer、宿主视角的网络地址、HTTPS/回环限制；不要只在模块机器上 curl |
| 模块已安装，新建库没有模板 | 清单是否声明 libraryTemplates、模块是否启用、模板 itemType/scope 与 revision 是否正确 |
| 搜索有结果，导入后层级不对 | sourceId 是否跨类型冲突，季/单集是否通过宿主导入 parentId/indexNumber |
| 有作品但找不到视频 | caps 与清单媒体类型交集、模块启停状态、libraryScope、providerIds 映射、发现超时与真实候选结果 |
| 返回 NoCompatibleStream 或黑屏 | 客户端是否强制转码、真实容器和编码、轨道描述、签名 URL 的实际响应；不能靠伪造编码或开启转码标记解决 |
| 回调 401/403，更新后更明显 | 是否误用用户令牌、仍缓存旧 Host-Token/Call-Ticket、首次 caps 预检没有凭据、权限是否声明 |
| 管理操作或模板创建得到 409 | 刷新模块清单和 revision 后重新执行，不跳过宿主版本检查 |

## 交付内容

提供模块源码、依赖清单及无秘密的 `manifest.json`；本地模式附实际 ZIP、目标平台和 SHA256，并写明：

- 兼容的 JMlab 版本/提交、模块类型、媒体类型、所需上游权限。
- 本地程序读取 `JMLAB_MODULE_LISTEN_ADDR/TOKEN/DATA_DIR`，不需要用户手动启动或填写端口；外部模式提供启动命令、宿主基址及连接 Bearer，业务密钥仍通过模块设置保存。
- 在“模块管理 → 添加模块”导入并配置，再搜索入库、创建模板库或指定视频模块适用库的步骤。
- 本地 ZIP 更新与外部服务/清单更新的区别，程序及 `.data` 文件需要单独备份；秘密留空保留、显式清除才删除；停用、卸载与外部服务数据的处理方式。
- 测试命令、结果及仍待验证的真实服务/客户端范围；问题发生时可提供的脱敏诊断信息。

模块项目内的说明可随该模块交付；在 JMlab 主仓库中，具体模块及其说明仍留在 `local-modules/`。本 Skill 的公开发布不代表用户授权公开具体实现、账号或外部服务资料。
