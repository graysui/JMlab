# JMlab 主程序架构

## 职责

Go 服务提供 API、权限、目录、任务、备份与模块运行时；React 前端提供媒体浏览、个人状态、设置及模块管理。SQLite 为默认存储，也提供 PostgreSQL 适配。HTTP 模块独立运行，主程序通过注册表调用相同协议。

宿主统一管理数据库，媒体与媒体流按模块身份关联。模块反向存储按模块 ID 隔离命名空间并加密。逻辑隔离不等于每模块一个数据库；外部服务可自行管理独立数据库。

## 主链路

1. 管理员导入清单，宿主校验配置并预检能力，成功后发布新的注册版本。
2. 搜索和导入明确指定信息模块；媒体保存原模块和来源身份，重复导入保持幂等。
3. 电影、独立视频及剧集层级统一入库，季属于剧集，单集属于季。
4. 视频模块按媒体类型和适用库发现候选，解析结果经宿主校验和中继。
5. Web 和 Jellyfin 共用权限、候选及播放链，用户状态和续播写入相同模型。

## 模块生命周期

清单目录位于 JMLAB_MODULES_DIR，默认是数据目录下的 modules。扫描支持新增、更新与移除，失败更新保留原实例。配置及启停加密持久化；热更新使旧注册版本的请求和凭据失效。

独立 HTTP 模块不随主程序打包。模块可使用任意语言实现，能力、管理操作和虚拟库模板由清单声明，前端按声明显示。宿主不会启动模块可执行文件。

## 数据与权限

主程序维护媒体、实体关系、虚拟库、合集、清单、用户状态、任务和审计。公开库和角色/用户授权共同决定目录、图片及播放的可见性。模块适用范围只决定是否提供媒体资源，不授予用户额外权限。

版本化迁移保留既有数据结构；兼容字段不代表内置相应业务。备份支持媒体数据和可选加密模块配置，恢复需要原主密钥。导入失败使用事务回滚；已提交但模块离线的恢复使用持久队列继续重载。

## 边界

事件是有界内存通知，重启或队列满可能丢失。HTTP 是当前可执行模块传输；Protobuf 是后续草案。主程序不提供实时转码，未知容器或轨道属性不伪造。客户端范围见[Jellyfin 说明](jellyfin-compatibility.md)，完整契约见[模块指南](module-developer-guide.md)。
