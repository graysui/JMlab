# JMlab 管理优先的前端重构实施计划

> 执行说明：用户已授权在当前会话按任务逐项实施并在完成后统一验证。实施前已核对仓库 AGENTS.md 与目标代码；本轮未提交或推送。

**Goal:** 将 Web 调整为配置管理优先的入口，让管理员完成从空安装到客户端连接的全过程，同时按现有角色权限提供独立管理区域。

**Architecture:** 沿用 React、TypeScript、React Router、原生 CSS、HLS.js 和现有 API 请求层。先建立页面边界，再按完整用户任务迁移布局与交互；宿主继续统一执行 Web 与 Jellyfin 的权限和观看状态规则。

**Tech Stack:** React 19、TypeScript 5.8、Vite 7、React Router 7、Go/chi、Playwright。

**Spec:** 本文件第一至第五节为设计规格，第六节为执行任务，第七节为验收与交付要求。

**状态：** 任务 1–8 已完成实施与回归。最终命令结果及未覆盖范围见文末执行记录。

## 一、已确定的方向与推荐选择

产品方向为：Web 主要用于配置管理，日常观看交给 Jellyfin 客户端；管理作为按角色开放的独立区域；允许重构。本轮实施依据用户随后提出的逐项执行授权。

推荐采用“管理独立布局 + 任务驱动的渐进迁移”。现有浏览和播放器继续可用，管理员默认进入管理概览，Editor 进入内容工作区，普通用户进入轻量浏览与客户端连接入口。

考虑过的方案：

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| 只拆 App.tsx，保持现有布局 | 行为风险较低，维护边界更清楚 | 无法解决管理入口分散和跨页往返，不足以实现目标 |
| 独立管理区，分批重构完整任务 | 产品方向明确，可逐批验证和回退 | 需要处理旧链接、页面上下文和角色差异；推荐 |
| 一次重写全部前端并替换 UI/状态体系 | 可统一全部实现 | 同时改变太多变量，播放和权限回归成本高，不采用 |

以下路由、布局、文件名和视觉值是本计划的推荐设计，并非用户逐项指定；实施前以用户审阅结果为准。

## 二、现状与必须保留的边界

代码阅读发现：

- App.tsx 约 2300 行，混合 Layout、路由、主题交互、首页、搜索、详情、播放器以及多种管理页面。
- 已拆出 ModuleCenterPage、DiscoverPage、LibraryBrowser、BackupAdminPage、SourceAdminPage、SettingsCenterPage 等，应复用其职责而不是重建第二份。
- 登录后统一跳转 `/`；首页以内容观看为主。管理分散在 `/settings/*` 和 `/admin/modules/*`。
- 模块页从 pathname 手动提取模块 ID，并使用 `tab` 查询参数；改变路由时必须同步该逻辑。
- 已有主题、设置搜索、模块筛选、搜索 URL 状态、滚动恢复和移动入口，迁移时保留有效行为。
- 当前浏览器回归直接断言设置导航、旧地址、页面标题及移动入口；布局改变后需要更新断言，同时保留权限和业务验证。
- App.tsx 内新建媒体库表单当前默认公开；本轮须明确呈现公开范围，不暗中改变服务器授权语义。

### 角色矩阵

| 能力 | Admin | Editor | 普通用户 |
| --- | --- | --- | --- |
| 管理概览 | 完整管理信息 | 已授权的运行及内容信息 | 不展示管理入口 |
| 模块安装、凭证、启停、更新 | 可操作 | 不可访问 | 不可访问 |
| 模块搜索并导入内容 | 可操作 | 可操作 | 不可访问 |
| 元数据、人物分类、合集、视频来源维护 | 依现有 API | 依现有 API，部分危险操作无权执行 | 不可访问 |
| 媒体库配置和授权 | 可操作 | 仅查看自己可见的媒体库，不提供编辑入口 | 仅浏览获授权内容 |
| 用户管理、备份恢复 | 可操作 | 不可访问 | 不可访问 |

### 路由与主入口

| 区域 | 推荐地址 | 规则 |
| --- | --- | --- |
| 角色入口 | `/` | Admin、Editor 到 `/manage`；普通用户到 `/browse`；未登录到 `/login` |

| 媒体库 | `/manage/libraries` | Admin 配置；Editor 只读，不发起用户清单或权限写请求 |
| 内容整理 | `/manage/collections`、`/manage/relations`、`/manage/sources` | 按现有操作权限呈现 |
| 维护 | `/manage/tasks`、`/manage/logs`、`/manage/statistics` | Admin、Editor，按 API 返回范围 |

侧栏只显示当前角色可访问项目；不增加全局仪表盘装饰。模块提供的榜单和自动更新仍放在模块上下文中，概览可链接过去。

手机使用顶栏标题和可访问的导航抽屉，保留完整功能；关闭抽屉后焦点返回触发按钮。表单单列，提交操作不能被固定栏和软键盘遮挡。表格在独立容器中滚动，页面自身不横向溢出。

### 视觉基线

- 复用品牌图标及现有深浅主题、蓝/薄荷/琥珀强调色变量；先沿用现有色值，再对实际文本与按钮组合测量对比度。
- 系统字体优先，增加合理中文回退；正文约 14–16px，表单标签不小于 14px，页面标题约 24–28px。
- 间距以 4/8/12/16/24/32px 为基准；控件主要触控区域至少 44×44px。
- 桌面侧栏建议 224px，内容区 24–32px 内边距；手机 16px；长表单可读宽度约 760–880px，列表可更宽。
- 配置页使用稳定分组与少量边界；运行结果使用明确状态和文字。保留现有主题偏好，不增加第二套主题系统。
- 样式随职责移动到布局、管理和媒体相关文件；删除废弃冲突规则，不通过全局选择器与反复叠加 !important 补丁实现。

## 四、关键用户流程

### 1. 空安装到 Jellyfin 客户端连接

`管理概览 → 安装并配置模块 → 添加内容 → 创建媒体库 → 设置视频模块适用范围 → 核对目标用户授权 → 客户端连接 → 在实际客户端验证`

这是一组可跳转、可返回的配置待办，不是强制顺序向导。每步展示已知状态、阻碍和当前角色可做的动作。

必须区分：未安装模块、无可用信息能力、无可见内容、无媒体库、无匹配视频能力、状态无法读取。请求失败不能转换成“未配置”。模块 active 只代表宿主可用状态，不保证每部内容都有视频；媒体库存在也不代表目标用户有播放授权。

配置状态来自现有 API；先核对 `/dashboard`、`/metadata/modules`、`/libraries` 与模块列表能支持的语义。已有数据不足时，不靠多个列表拼接推断全局就绪，也不为了统计把全部媒体拉到浏览器。必要时才新增受权限保护的汇总接口，实施前明确状态、范围和测试。

页面不得声称“Jellyfin 已连接”或“播放已验证”，除非存在可核实的实际证据。本轮默认只提供“配置检查”和“客户端实测指引”。不以 localStorage 勾选作为配置完成依据。

Editor 只看到自己能做的内容任务；遇到缺模块、缺库或缺授权，说明需要管理员处理，不显示无权操作按钮。

### 2. 模块安装与配置

主入口为模块列表；添加页说明 ZIP、网址和外部 JSON 各自用途。阶段清楚区分“读取信息 → 填写配置 → 安装或保存 → 运行检查 → 后续操作”。

配置页按模块声明渲染；秘密字段明确保留、替换、清除，空输入不默认删除。能力决定后续按钮：信息能力链接到预选模块的添加内容页，视频能力链接到适用媒体库，复合模块提供两条入口并突出当前缺少的步骤。

更新失败保留当前工作版本和可恢复输入，显示实际服务端原因；密码类输入只保留必要内存，不存 URL、日志或持久化配置。停用、卸载与更新文案对齐实际数据保留行为。

### 3. 添加内容与整理媒体库

添加内容页明确“搜索模块内容”和“搜索已入库内容”的区别；保留模块、类型、关键词和分页上下文。重复添加沿用服务端既有合并语义，不新增重复记录逻辑。

导入成功后展示“查看内容”“创建或查看媒体库”等下一步，说明入库不保证已匹配媒体库或视频。剧、季、集按层级操作；批量导入失败保留已完成结果，可继续处理剩余内容。

创建媒体库按“模块 → 模板 → 可选范围 → 名称及筛选 → 可见范围 → 保存”组织。基础配置可读，高级 JSON 按需展开，不能破坏无法用可视化表达的旧筛选。

公开与指定授权必须有清楚说明，沿用既有 API 默认和权限语义，不因 UI 重构扩大公开范围。创建成功后链接到授权和视频模块适用范围；不复制另一套配置表单。Editor 仅查看已有范围。

### 4. 日常维护与恢复

任务状态沿用宿主 queued/running/succeeded/partial/failed/cancelled，不伪造进度。任务、视频来源、模块及媒体之间保留上下文链接；失败时能回到原对象修复并重试。

备份、恢复、删除、停用等操作确认具体对象及影响。普通保存不额外弹窗。恢复后的模块程序缺失与配置恢复结果分开说明。

### 5. 客户端连接与 Web 保底能力

连接页展示服务端可信配置的公共访问地址、当前用户名、Jellyfin 连接方式和简短步骤；复制成功或失败有反馈。不得复制密码或令牌，不从不可信请求头直接生成可复制地址。

先核对现有认证后系统信息能否提供 PublicURL；若没有，则新增最小的认证后连接信息接口，只返回公共地址和必要展示信息，保持 Jellyfin 既有响应稳定。

说明无实时转码，网络可达不等于真实媒体可解码。保留 Web 浏览、详情、选源、续播、字幕和观看状态；这些功能用于查看与验证，降低首页优先级，不删能力。

## 五、代码拆分方案与约束

推荐目录边界（最终文件按迁移需要创建，不预建空壳）：

```text
src/
  App.tsx                         应用组合入口
  app/AppRoutes.tsx               路由树、显式旧路径映射
  app/RouteAccess.tsx             登录及角色访问边界
  app/routeAccess.ts              入口计算、站内返回目标校验
  layouts/ManagementLayout.tsx    管理导航、面包屑、Outlet
  layouts/BrowseLayout.tsx        浏览导航和 Outlet
  components/ThemeMenu.tsx        现有主题交互
  components/media/               ItemCard、ItemGrid、ItemPoster、ImageGallery
  components/management/          实际复用的标题、反馈与确认控件
  hooks/useThemePreferences.ts    现有主题读取及保存生命周期
  hooks/useScrollRestoration.ts   现有列表滚动恢复
  lib/navigation.ts              管理条目、分组、允许角色和主路径
  pages/manage/                  概览、库、用户、合集、关系、任务、日志、统计
  pages/browse/                  原首页、搜索、详情、关系浏览、播放器
  pages/LoginPage.tsx
  pages/ProfileSettingsPage.tsx
  pages/ClientConnectionPage.tsx
  pages/                         复用已存在模块、导入、备份等页面
  styles/                        随任务迁移布局及业务样式
```

不以行数作为拆分完成标准：App.tsx 不再承载页面业务；页面按完整职责独立；不得通过一个巨型自定义 hook 或公共 utils 文件转移耦合。仅对重复且语义一致的 UI 提炼组件。

接口约定：

- `defaultRouteFor(user: User): string`：Admin/Editor 返回 `/manage`，其余返回 `/browse`。
- `safeReturnTo(candidate: string | null): string | null`：只接受站内合法路径；授权仍由路由边界判断。
- `RouteAccess({ roles?, children })`：未登录保留站内返回目标，登录后无权显示权限状态，先阻止受限页面挂载。
- `navigation.ts` 定义导航项的 id、label、to、group、roles；导航和路由访问规则共享角色判断，不复制权限清单。
- 沿用 `apiFetch<T>`、`readSession`、`saveSession`、`userHasRole` 和会话变化事件，不重写认证与 CSRF。
- 共享数据模型优先归位 models.ts 或对应业务类型文件；页面局部表单类型留在所属页面。

不做：替换 UI 框架、全量迁移 React Query、修改模块协议、扩大角色权限、重写播放内核、添加具体业务模块、修改数据库结构以适应纯布局调整。

## 六、分阶段实施任务

### 任务 1：建立基线并提取应用边界

**文件：** App.tsx、main.tsx、lib/models.ts；新增 app/AppRoutes.tsx、pages/LoginPage.tsx、pages/ProfileSettingsPage.tsx、ThemeMenu 及主题 hook；按需提取媒体公共组件。

**输入：** 当前路由、主题与会话事件。
**输出：** 已提取页面不从 App.tsx 反向导入组件；建立基础应用边界。此任务保持原有可见路径和行为，未迁出的管理页面保留到任务 7；App 最终只组合应用是任务 7 的完成条件。

- [x] 在临时宿主中记录管理员、Editor、普通用户当前登录及导航；阅读现有相关回归，区分既有问题和改动引入问题。
- [x] 按实际引用提取路由、主题、登录、个人偏好及必要共享类型，消除循环依赖；不同时改页面布局。
- [x] 将播放器及其图片/媒体依赖按完整职责归位，保持播放状态生命周期和事件回写时机。
- [x] 运行前端构建与现有 app、ui-experience、settings-flow 相关回归，确认行为基线。

**完成条件：** 构建通过，既有登录/主题/播放行为回归通过；页面拆分没有新增运行错误。

## 七、验收、风险与执行规则

### Review Focus

1. 普通用户或 Editor 直接输入深链接：不能挂载无权限业务组件或读取模块凭证、用户清单、备份信息；任务 2、5 的前后端权限断言覆盖。
2. 配置 API 暂时失败、模块热停用或卸载：未知状态不能伪装成无配置或就绪，旧 moduleId 可恢复选择；任务 3、4、5 覆盖。
3. 旧书签含 itemId、tab、筛选、hash：迁移后保留上下文，无重定向环；任务 2 覆盖。
4. 反向代理公共地址和复制失败：使用可信公开地址，不复制登录令牌，不误报成功；任务 6 覆盖。
5. 导入只完成部分剧集、客户端不支持格式：保留已完成数据，可继续导入，不声称全部可播放；任务 5、6、8 覆盖。

### 检查命令与证据

- 前端每个代码批次：`npm --prefix web/app run build`，预期 TypeScript 与 Vite 构建成功。
- 浏览器按任务缩小范围：`node scripts/check-web.mjs tests/settings-flow.spec.mjs` 等；最后运行 `node scripts/check-web.mjs`。依赖和浏览器未准备时先说明并准备隔离环境，不使用部署数据。
- 前端行为必须实际启动应用操作，查看控制台和网络失败；Playwright 与人工操作共同核对成功、失败、恢复路径。
- 后端改动：运行受影响包测试；跨包或权限变更运行 `go test ./...`，按 CI 运行 `go vet ./...` 与 `go test -race ./...`。
- 文档改动：`python scripts/check-public.py`、`go -C scripts/check-docs run .`。仓库要求新增公开文档被 README 直接引用；不要为计划放宽公开检查。
- 视觉矩阵：320、375、768、1280px × 深浅主题，检查页面无整体横向溢出、提交按钮不被覆盖、44px 主要触控目标、键盘与焦点。
- 对比度通过计算样式验证：普通文本至少 4.5:1，大文本至少 3:1；截图用于展示，不能替代计算和操作证据。
- 弹窗/抽屉检查 Escape、焦点进入/返回、键盘操作；长模块名、长中文标题与错误信息可正常换行。

### 完成定义

- Web 的默认角色入口和导航符合管理优先定位，普通用户仍有完整的个人与浏览入口。
- 新管理员能根据真实状态完成安装、内容、库、范围、权限与客户端连接，每一步都能返回和恢复。
- 原有模块安装、媒体权限、Jellyfin 行为、观看进度及 Web 播放能力无回归。
- App.tsx 只负责应用组合，路由、布局、页面及业务类型有清楚归属；没有将复杂度整体转移到另一个大文件。
- 所有实施批次有可复核的检查记录；未实际验证的真实媒体解码、设备和客户端版本明确列出。

### 主要风险与控制

- **路由迁移影响大：** 先测试旧地址和角色矩阵，再迁移链接；先完成外壳边界，不与所有业务改造一起提交。
- **配置状态容易被过度推断：** 状态注明范围，未知明确显示；不以内容条目数或模块 active 代表可播放。
- **样式存在耦合：** 随页面检查具体选择器及响应式覆盖，逐批删除废弃规则；不进行全量 CSS 重写。
- **公开权限和敏感字段：** 保留既有语义与服务端授权，新增 UI 不隐式清空凭证或放宽可见范围。
- **真实客户端不可用：** 先验证夹具与兼容接口，实际设备和媒体实测留为明确验收项，不能用页面截图替代。
